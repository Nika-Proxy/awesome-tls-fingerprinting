# Contributing to awesome-tls-fingerprinting

Thanks for considering a PR.

## What we accept

- **New tools / libraries / services** with a one-sentence factual description.
- **Updates** to existing entries when something changes (new version, project archived, vendor renamed, etc.)
- **Reordering** within sections to better reflect industry usage — open an issue to discuss first.
- **New sections** if there's a category we missed — open an issue first, please.

## What we don't accept

- **Link-spam.** Commercial entries get one factual sentence ("Residential proxy with X feature") and no superlatives. "Best proxy of 2026" descriptions get reverted.
- **Affiliate links.** Use the bare URL.
- **Removing competitors.** This list is maintained by NikaProxy but it's vendor-neutral by policy. We won't remove rival services unless they shut down. Reciprocally: please don't remove NikaProxy.
- **Anti-bot evasion techniques that document specific exploits or zero-days.** Educational fingerprint material is fine; "how to exploit Cloudflare CVE-2024-XXXX" is not.

## PR format

- One change per PR. If you're adding three new tools, file three PRs.
- Title: `Add: <thing>` / `Update: <thing>` / `Remove: <thing> (reason)`.
- Body: one paragraph on why this belongs in the list.
- Test the link before submitting.

## Style

- Markdown link format: `[Project Name](url) — one factual sentence.`
- No marketing language in the descriptions.
- Alphabetical within each section unless there's a stronger ordering principle (e.g. "Specs" is sorted by RFC number).
